# OpenConvert — Architecture Decision Record (ADR), v2

**Status:** Final for v1 planning. Written by the Chief Architect after two rounds of delegated research (R1–R10, V1–V2) and an adversarial red-team review (RT). All three are in `research/`.
**Date:** 2026-09-09
**Principle:** Deterministic first. AI where necessary. Validate everything. Repair only what is broken.

Each decision states: Decision · Why · Alternatives considered · Why rejected · Residual risk. Changes forced by the red team are marked **[RT]**.

---

## D1. Language: **Rust (core library + CLI engine), TypeScript (UI), Python (offline eval/corpus tooling, never shipped)**

**Why.** Low RAM, fast startup and small binary (priorities 1–3) require a native, GC-free core; Rust adds memory safety on the one component that eats untrusted input all day. Rust has the best permissively licensed glyph-level PDF access (`pdfium-render` + `lopdf`) and first-class snapshot/property testing (`insta`, `proptest`). TypeScript keeps the UI in the maintainer's existing skill set. Python does corpus curation, ground-truth generation, metrics and plots — and is never a build or runtime dependency (CI release job runs without Python).
**Alternatives.** Python+Qt (best PDF libs but 50–120 MB packages, slow start, PyMuPDF is AGPL), Electron (pdf.js gives item-level geometry only; ~244 MB), .NET/Avalonia (PdfPig is superb but no production WebView; LLamaSharp lags upstream), Go/Wails (no permissive glyph-level PDF library), Flutter (viewer-grade PDF only).
**Residual risk.** Rust learning curve for a solo maintainer. Mitigation: no `async` in the pipeline core (CPU-bound; `rayon` for per-page parallelism), no lifetimes in public APIs (owned data + arena indices), `#![forbid(unsafe_code)]` outside the pdfium wrapper, clippy `-D warnings`, snapshot tests that make refactors cheap. Budget 4–6 weeks of reduced velocity.

## D2. Desktop framework: **Tauri 2.x**

**Why.** ~9 MB shell vs ~244 MB Electron for the same app (gethopp 2025), ~2× lower RAM, native drag-drop delivers file *paths*, first-class `externalBin` sidecars (one per target triple), mandatory Ed25519-signed updater.
**Alternatives.** Electron (rejected on priorities 1–3; its hidden-window screenshot advantage is obtainable in CI with Playwright, which also covers WebKit), pure-Rust UIs (no HTML renderer → no EPUB preview), Wails (v3 beta; Go PDF gap).
**Residual risk.** WebKitGTK version spread on Linux; Tauri cannot screenshot hidden windows; **[RT]** the Tauri capability system only scopes what the *app* spawns — processes spawned by the engine are outside it. Mitigations: conservative CSS baseline in the control-panel UI; visual QA in CI; the app passes the engine exactly one argument (a job-spec file path in an app-controlled directory) so the argument allow-list is meaningful.

## D3. PDF parser: **PDFium (BSD-3) via `pdfium-render` 0.9.x (MIT/Apache-2.0), vendored `bblanchon/pdfium-binaries` (SHA-256 pinned, code-signed in CI), plus `lopdf` (MIT) for the object model; all behind an internal `PdfBackend` trait**

**Why.** Independent benchmark: `pypdfium2` matches PyMuPDF on speed (0.1 s) and beats it on quality (97 % vs 96 %) under a permissive license. Per-character API (verified names): `tight_bounds()`, `loose_bounds()`, `origin()`, `matrix()`, `angle_degrees()`, `unscaled_font_size()`/`scaled_font_size()`, `font_name()`, `font_weight()`, `font_is_italic()`, `render_mode()` (drop invisible OCR layers), `fill_color()`, `is_generated()` (filter synthesized spaces), `is_hyphen()`. Renders pages (OCR input, contact sheets). Prebuilt binaries weekly for all desktop targets; loaded at runtime via `libloading`, so the app binary stays small and PDFium can be updated independently. `lopdf` supplies outlines (belt-and-braces), `/StructTreeRoot` (hint only), `/Metadata` XMP, `/Producer`/`/Creator`.
**Alternatives.** MuPDF (best extraction engine, AGPL-3.0 or commercial → forces AGPL on OpenConvert and every fork), Poppler (GPL), pdf.js (item-level geometry), `hayro` (pure Rust, experimental, no encryption, no char-level font signals), `pdf_oxide` (unverified vendor benchmarks).
**Residual risk. [RT]** `has_unicode_map_error()` was not found in `pdfium-render` — the broken-CMap detector falls back to U+FFFD/PUA share + dictionary hit rate (Phase 1 spike records which). Runtime binding means a PDFium ABI mismatch is a runtime error — the engine probes the library version at startup. `libpdfium.dylib` must be signed with our Developer ID in CI (macOS Hardened Runtime library validation); we do **not** use `disable-library-validation`. A second backend (`hayro`) is post-v1; `pdftotext` (external, CI only) is the differential string oracle.

## D4. OCR: **Tesseract 5 CLI, used when available. v1 = detect image-only/mixed pages always; use a system-installed `tesseract` if found; ship an optional signed "OCR pack" (tesseract + tessdata_fast) later as a post-install download**

**Why.** Only engine that is CPU-only, Apache-2.0, small (deu fast model 1.45 MB), emits TSV with word boxes + confidences, and supports German and Turkish. Calibre refuses image-only PDFs — a differentiation opportunity — but distributing Tesseract on three platforms (no official prebuilt binaries; signing/notarization obligations) is a real commitment for one maintainer. **[RT]** Therefore v1 first integrates the *user's* Tesseract (Homebrew/apt/UB-Mannheim), with a copy-pasteable install hint when a scanned PDF is detected, and the packaged OCR pack follows once the CI build recipe (vcpkg static triplets) and signing are proven.
**Alternatives.** PP-OCR via ONNX (better accuracy/size; community Rust ports only; ONNX Runtime weight), platform OCR (Apple Vision / Windows.Media.Ocr — future optional backends), `ocrs` (Latin-only preview), Surya/VLMs (GPU-class or revenue-gated).
**Residual risk.** Users without Tesseract get page images + a warning instead of text for scanned pages.

## D5. EPUB generator: **hand-rolled EPUB 3.3 (`quick-xml` + `zip`) through a typed XHTML builder whose types encode the HTML content model, plus legacy `toc.ncx`**

**Why.** The output *is* the product and needs byte-level control: `epub:type` semantics (`footnote`/`noteref`, `chapter`, `bodymatter`, `frontmatter`, `backmatter`), `<figure>/<figcaption>`, `page-list` nav from source page numbers, EPUB Accessibility 1.1 metadata, correct manifest `properties` (OPF-014 is a top converter error), deterministic zip (mimetype stored first, fixed timestamps, sorted entries), ~260 KB XHTML split at paragraph boundaries (Calibre's ADE-derived default — the one *anchored* size number), `dcterms:modified`, stable `urn:uuid` across re-conversions. **[RT]** A hand-rolled emitter's likely bugs are content-model violations (`<figure>` inside `<p>`, `<a>` in `<a>`, `<aside>` in phrasing context) that a well-formedness check cannot see — so the builder makes illegal markup unrepresentable (`Flow` / `Phrasing` / `Sectioning` types). Emit EPUB 3.3 only; JPEG/PNG by default (WebP is legal in 3.3 but reader support lags); no font embedding by default; never `<script>`, never `remote-resources`, no DOCTYPE entity declarations.
**Alternatives.** `epub-builder` (MPL-2.0, EPUB 3.0.1, no content model), `ebooklib` (Python, AGPL).

EPUB validation: **Tier 1 internal Rust validator (always on, measured against EPUBCheck's public test corpus) · Tier 2 EPUBCheck as a hard CI gate, and in-app via an optional "validation pack" (jlink'd minimal JRE + epubcheck.jar, ~40–50 MB, same download mechanism as the model) · Tier 3 Ace by DAISY in CI**

> does not offer it. `packs.toml` names it as a `[[deferred]]` entry with no pins, the Packs screen
> says it arrives in a later version, and the app and `openconvert` refuse to install it with that
> reason. Tier 1 (always on) and Tier 2/3 in CI are unchanged. VD-f (the Java runtime's licence) is
> deferred with it. See `docs/DECISIONS_LOG.md`, 2026-09-23.

**Why.** EPUBCheck (BSD-3) is authoritative but Java. **[RT]** Bundling a JRE in the base install violates priorities 1–3, but refusing an *optional* 45 MB pack while offering a 1 GB model download was inconsistent — so the pack exists. Tier 1 covers OCF/OPF/nav structure, RSC-005/RSC-012/OPF-014/PKG-007 classes, plus book-specific checks: `noteref`↔`footnote` bijection, every `page-list` target resolves, non-empty `alt`, no scripts/remote resources, case-insensitive entry-name collisions, image-count parity with extraction. Its coverage is a CI-tracked number (per-message-ID parity on EPUBCheck's own corpus), not an assertion.
**Alternatives.** `epubveri` (pure Rust, 98.8 % parity, pre-1.0, AGPL-3.0 → forces AGPL). Watch, don't adopt.

## D7. Visual/structural QA: **no bundled renderer. In-app = render-free structural checks + a visible "approximate preview" in the Tauri webview. CI = Playwright DOM assertions (Chromium on every PR; WebKit nightly); screenshots only at release time, one OS, human-reviewed**

**Why.** Tauri cannot capture hidden webviews (wry #1358, tao #289); bundling Chromium is ~281 MB; pixel comparison PDF-vs-EPUB is meaningless under reflow. What catches conversion bugs is structural: text conservation (D13), image-count parity, heading-tree sanity, footnote bijection, duplicate detection, DOM overflow (`scrollWidth > clientWidth`) at three viewports. **[RT]** Per-OS golden screenshots are the highest-maintenance, lowest-yield test artifact; the surface is deliberately reduced.
**Residual risk.** In-app hidden-window DOM measurement is undocumented → Phase-6 spike with fallback (CI only).

## D8. LLM runtime: **`llama-server` (official llama.cpp release binary per OS, single CPU binary with runtime ISA dispatch via `GGML_CPU_ALL_VARIANTS`; Metal on macOS arm64) bundled as a Tauri `externalBin` on all platforms (10–18 MB), spawned lazily on `127.0.0.1:<ephemeral>` with a per-run `--api-key`, `-np 1`, idle-kill**

**Why.** Crash isolation for long conversions over untrusted PDFs; `kill()` returns 100 % of model RAM; the app binary never links GGML; grammar-constrained decoding (`json_schema`/GBNF in the request) over HTTP makes every LLM call mockable in `cargo test`; Ollama and any OpenAI-compatible endpoint speak the same protocol. **[RT]** Bundling (not downloading) the server binary removes a Gatekeeper/notarization failure class on macOS at negligible size cost; only the *model* is downloaded. **[RT]** `--cache-reuse` (KV shifting) works only for dense-attention models; hybrid recurrent models (Qwen3.5) cannot be partially erased and rely on exact-prefix slot reuse and `--context-checkpoints`. Prefix discipline is therefore a design element: one byte-identical system prefix (taxonomy + few-shot) shared by all call types, `-np 1`, one warm slot per book.
**Ownership. [RT]** The engine accepts `--llm-endpoint URL --llm-api-key-file PATH`; if absent it spawns and owns its own server (killed on exit, nested job object on Windows, `setsid`+`kill(-pgid)` on Unix). The desktop app supplies a long-lived, app-owned server so the model loads once per batch. Thinking is disabled per request (`chat_template_kwargs: {"enable_thinking": false}` on `/v1/chat/completions`, plus `/no_think` for the Qwen3 family) and asserted absent in output.
**Alternatives.** In-process `llama-cpp-2` (UB-prone C API, clang/cmake in our build, no isolation), require Ollama (second app, global model store, `num_ctx` 2048 default silently truncates, version drift), mistral.rs (plan-B engine), ONNX Runtime GenAI.

**Why. [RT]** Research round 1 recommended Qwen3.5-2B (newest, 201 languages, OmniDocBench 79.8). Every unverified risk in the plan concentrates in that one component. Because swapping the default is one line in a data file, the plan defaults to the safe model and promotes the newer one on evidence. Qwen3-1.7B: dense transformer, official GGUF, Apache-2.0, thinking disabled via `enable_thinking=False` or the `/no_think` soft switch, **119 languages and dialects per the Qwen3 release blog, which lists Turkish and German explicitly** (the model card states "100+ languages" and explicitly names llama.cpp among supported runtimes) — verified 2026-09-09; KV-shift cache reuse works, well-exercised in llama.cpp since 2025. The LLM tasks are flat-enum classification over 300–1,200-token inputs — the axis on which a 1.7B dense and a 2B hybrid differ least.
**Promotion gate (Phase 9, `eval/model_gate.py`, two fixed reference machines L = 4c/8t AVX2 x86 16 GB, M = base Apple M-series 16 GB):** G1 loads/health; G2 200/200 grammar-constrained outputs parse and pass semantic assertions; G3 prompt renderer matches reference tokenizer on 20 fixtures, thinking absent 200/200; **G4 full per-book call set ≤ 50 s on L for the reference 300-page book AND LLM share ≤ 25 % of total wall-clock including the LLM** (both conditions, not alternatives: at the 0.5 s/page budget a 300-page book is ~150 s deterministic, so 25 % of the total permits ≤ 50 s of LLM); **G5 second identical call set ≤ 40 % of the first (prefix reuse)**; G6 peak RSS ≤ 2.5 GB at `-c 8192 -np 1`, RSS returns to baseline within 2 s of kill; G7 McNemar non-inferior on all four decision tasks vs the incumbent and significantly better on ≥ 1; G8 ≥ 95 % on 100-item DE and TR flat-enum probes with zero out-of-alphabet output; G9 GGUF reproducible from official safetensors at a pinned revision with a SHA-256 we produced. Re-run on every llama.cpp bump. (All numeric gates are `source = provisional` in `thresholds.toml`.) **Results:** the machine-readable run files under `eval/results/model_gate/<model>__<build>__<machine>.json` — per-gate pass/fail, measured value, threshold, machine descriptor, llama.cpp build tag, date — are the **source of truth**; `docs/MODEL_GATE.md` is the human-readable table *generated* from them (`eval/model_gate.py --render-table`) and is never hand-edited.
**Distribution.** Never in the installer. The in-app model manager (Rust, `oc-net`) — or `openconvert model pull` for CLI users — downloads from a pinned `huggingface.co/<repo>/resolve/<commit-sha>/<file>` URL, verifies SHA-256 against a hash compiled into the app's model registry (`models.toml`, shipped with the app, no remote registry in v1), and writes LICENSE + NOTICE beside the file. Downloads never happen during a conversion. First-run UI shows size, RAM estimate, CPU expectation and license.
**Excluded.** Llama 4 and Llama 3.2-vision (EU-domiciled developers excluded), EXAONE (non-commercial), LFM2.5 (revenue-capped license, no Turkish), Gemma 4 (now Apache-2.0 — a legitimate *alternate* candidate, but its Per-Layer-Embeddings footprint is unresolved: E2B = 5.1 B params with embeddings, 0.74–3.5 GB peak RAM by platform), document VLMs (English-only, 15–60 s/page CPU).

## D10. Model format **GGUF** · inference strategy **sidecar** (D8) · BYO provider strategy: **one OpenAI-compatible HTTP client behind an `LlmProvider` trait**

Two implementations in v1: `LocalSidecar` (server we own) and `OpenAiCompatible` (base URL + optional key). Ollama = `OpenAiCompatible` with auto-detection on `localhost:11434` and its `format` field for JSON schema (and an explicit `num_ctx` override, since Ollama's default 2048 would truncate prompts). LM Studio and other local servers = custom endpoint. **No cloud preset in v1.** Thinking control is a trait method, `thinking_control()`: `LocalSidecar` sends `chat_template_kwargs: {"enable_thinking": false}` on `/v1/chat/completions`, Ollama sends `think: false`, and generic OpenAI-compatible endpoints get `/no_think` appended to the shared system prefix for Qwen-family models — and for every provider alike, any `<think>` content or non-grammar output fails gate S and falls back deterministically, so a provider that ignores the lever degrades safely. A non-loopback endpoint requires an explicit consent toggle naming the host and stating that document text leaves the machine; the conversion report records it.

## D13. Application architecture

**D13.1 The engine is a library; the CLI is its face; the GUI runs the CLI as a supervised subprocess. [RT]** `oc-core` (library) is linked by both `openconvert` (CLI) and the desktop app. v1 executes conversions out of process because that buys deterministic RAM reclamation and cancellation-by-kill for free; crash isolation matters only at the C/C++ boundaries (PDFium, llama.cpp), and the boundary can move later without relitigating. One code path for GUI, CLI, CI and benchmarks.

**D13.2 IPC protocol (CLI ↔ GUI). [RT]** stdin = control (NDJSON: `cancel`, `ping`); **stderr = events** (NDJSON, one object per line, ≤ 8 KiB, envelope `{v, t, seq, ts_ms}`: `hello{engine_version, ir_version, protocol, pdfium_version, capabilities}`, `job`, `stage{name, begin|end}`, `progress{stage, done, total}` coalesced ≤ 10/s, `warning{code, severity, args, block_ids}`, `llm{call_id, purpose, cached, tokens_in, tokens_out, ms}`, `heartbeat` every 2 s, `done{status, report_path, output_path}`, `fatal`); stdout = data only (`--dump-stage -`). GUI hard-errors on protocol/IR version mismatch. Cancellation: atomic flag polled at stage boundaries and inside per-page loops; engine reaches `done{cancelled}` within 2 s, deletes temp files, exits 3; supervisor terminates the job after 5 s. Exit codes: 0 ok, 1 failed (report written), 2 usage, 3 cancelled, 101 panic. Output written to `<out>.oc-tmp-<rand>` in the destination directory and renamed atomically on success. Process supervision: Windows Job Object (`KILL_ON_JOB_CLOSE`, `PROCESS_MEMORY`, `JOB_TIME`) + `CREATE_NO_WINDOW`; Unix `setsid` + `kill(-pgid)`, Linux `PR_SET_PDEATHSIG`; engine installs signal/console-ctrl handlers that tear down children. Resource limits always on: `--max-pages` (3000), `--max-memory` (4 GiB via job object / `RLIMIT_AS`), per-stage deadlines, max image pixels (100 MP declared), max decompressed stream bytes (256 MB), max output size. The GUI passes one argument: the job-spec path.

**D13.3 IR, not Markdown.** A typed document tree (`oc-model`) with per-block provenance (page, bbox in normalized page space, source run ids), per-decision `Confidence { method: Deterministic|Llm|User, signals, escalated }`, a **span-based text ledger**, and a decisions log. Canonical JSON serialization (sorted keys, geometry rounded to 0.01 pt *at serialization only*, no NaN/Inf, NFC strings) with `ir_version`; block ids are `base32(blake3(page_index ‖ bbox rounded to 1 pt ‖ first 64 NFC chars))[..10]` with collision suffix — changing the derivation bumps `ir_version` and invalidates caches and overrides. Geometry lives in one normalized space fixed at extraction (origin top-left, y down, PDF points, after `/Rotate` and CropBox offset) — an asserted invariant, because mixing CropBox and image space silently deleted body text in a shipping 2026 tool.

**D13.4 Conservation law (replaces "character multiset" Gate L). [RT]** Normalization `N = strip(U+00AD) ∘ expand_ligatures(U+FB00–FB06) ∘ NFC` is applied exactly once at extraction; NFKC is forbidden; text is never case-folded (Turkish-aware folding builds lookup keys only); superscript status is captured from geometry before `N`. Two baselines: `C_raw` (after extraction) and `C_0` (after `N`, overdraw dedup, OCR-layer dedup) — the retention denominator. Every stage is statically `Conserving` or `Budgeted` with a closed `Reason` enum (`SoftHyphen, LigatureExpand, GeneratedSpace, RunningHeader, RunningFooter, PageNumber, OverdrawDedup, OcrLayerDuplicate, Dehyphenate, Ocr, DecorativeGlyph, Watermark, ClippedOffPage, HiddenText, UserOverride` — fifteen variants: `ClippedOffPage` is geometric (wholly outside the CropBox, or removed by a clipping path), `HiddenText` is rendered but not visible (render-mode-3 text on a page that is not an OCR sandwich, or a fill colour within the delta-E tolerance of the local background); both are owned by `ingest`) and per-reason budgets as fractions of `|C_0|` (provisional: furniture ≤ 0.04, overdraw ≤ 0.02, OCR-layer dup ≤ 0.60 per page, dehyphenate ≤ 0.005, decorative ≤ 0.002, others ≤ 0.001, global non-OCR removal ≤ 0.08). Invariants checked after every stage: I-1 `C(D_i) ⊎ Added = C(D_{i+1}) ⊎ Removed`; I-2 reasons declared; I-3 conserving stages have empty ledgers — **reading order, block typing, headings, structure roles, verse/quote, lists, footnote linking, image anchoring, chapter splitting, XHTML serialization, and every LLM edit are Conserving**; I-4 budgets; I-5 dehyphenation removes exactly one `U+002D`/`U+2010` and nothing else; I-6 OCR is Added-only and **region-scoped**: an `Ocr` ledger entry is permitted on any page region whose bbox contains no PDF text runs — the whole page on an `image-only` page, each uncovered image region on a `mixed` page — and every such region is marked `provenance = ocr` and excluded from source retention; I-7 end-to-end `C(EPUB) ⊎ Removed_all = C_0 ⊎ Added_all` is a release gate. Cost: a scalar histogram per stage (sub-millisecond); ledger entries are spans. What it does **not** catch: a wrong dehyphenation join, a wrong heading level, a wrong reading order — those have their own checks.

> **Amendment, 2026-09-20 (Phase 7.5).** `C(·)` is taken **after canonical decomposition
> (NFD)**: the multiset is of the non-whitespace scalars of `NFD(text)`, not of `text`.
>
> *Why a canonical form.* The three components of `N` are not equally expressible —
> `strip(U+00AD)` has `SoftHyphen` and `expand_ligatures` has `LigatureExpand`, but NFC has no
> `Reason` and this enum is closed — so a canonical *singleton* (U+2126 OHM SIGN → U+03A9, and
> likewise U+212B, U+212A, U+1F71 and the rest of the 1 120 code points NFC rewrites) breaks
> I-1 with nothing lost. Seven corpus documents were refused for exactly that.
>
> *Why decomposition and not composition.* Composition depends on **adjacency**: `u` followed
> by U+0308 composes only when the two are next to each other. A stage cuts its text where it
> likes — the glyph stream is one sequence in draw order, the runs are many in reading order —
> so a composing law gives two answers for one book. That was measured, not feared: four more
> documents were refused after the first attempt, an umlaut drawn as two glyphs and assembled
> into two non-adjacent runs. Decomposition expands each character independently, and the
> canonical reordering that follows cannot change a *multiset*, so `C` is the same whatever
> pieces the text arrives in. The law is granularity-independent by construction instead of by
> every stage remembering to cut in the same place.
>
> Both fold the same equivalences, because two canonically equivalent strings have the same
> decomposition by definition. NFKD stays forbidden alongside NFKC: `ﬁ` is not `fi` and `²` is
> not `2`. The `Reason` enum stays closed at fifteen. `N` itself is unchanged and still
> composes — this is about how `C` is *measured*, not about what the book contains.

**D13.5 Escalation and the four gates (LLM edits).** Deterministic → escalation predicate true (v1 uses structural predicates, not calibrated scores; see D17) AND `ai.enabled` AND budget remains → LLM → gates: (S) parses against the grammar, ids bijective, enums legal, arity correct; (L) the edit is `Conserving` (labels/levels/roles/CSS classes only); (V) a fixed tuple of region-valid statistics (duplicate-line ratio, top-n-gram ratio, non-alpha-word ratio, heading-tree sanity) does not worsen beyond epsilon — else revert; (D) the deterministic answer stands as fallback and is recorded. **Label authority ≠ deletion authority:** the LLM may propose `running_head`; only the deterministic furniture remover deletes, and only when its cross-page repetition evidence independently agrees.

**D13.6 LLM call shape.** Never per page. v1 has **four** LLM tasks, all once-per-book over compressed inventories with geometry pre-digested into categorical words (never raw coordinates — LayTextLLM: a 7B model scores 34.3 % with coordinates-as-text): (1) metadata from pages 1–3 (~300 tokens; verbatim-substring validation), (2) heading-style inventory → role per cluster (~600 tokens; pre-gate: ≤ 24 clusters, body cluster ≥ 60 % of chars; held-out self-consistency check on 8–10 unseen runs, reject mapping on > 20 % disagreement; per-segment clustering when the body font changes across page ranges), (3) book-structure roles as **boundary/run-length output** (`frontmatter_end_idx`, `part_boundaries[]`, `backmatter_start_idx`) with chunking + overlap above 200 headings, (4) verse/quote/preformatted for ambiguous indented blocks (≤ 30 blocks/book, batched at **exactly 10 blocks per call**, so task 4 costs at most 3 calls and leaves 5 for tasks 1–3 including `book_structure` chunking). Dehyphenation residuals via LLM are **dropped from v1** — a kilobyte-scale logistic/CRF classifier over character features lifts keep-hyphen recall from ~32 % to ~86 % at no accuracy cost and is cheaper, more accurate and more testable. Budgets: ≤ 8 calls/book **total** (one budget, no per-task sub-budget), ≤ 1,500 output tokens/call, LLM wall-clock share ≤ 25 % of **total** wall-clock including the LLM (hard stop). When the call budget would still be exceeded, tasks are dropped in a fixed degradation order: `verse_quote` first, then `book_structure` chunks beyond the first, then `heading_roles`, **never `metadata`**.

**D13.7 Validate → repair loop. [RT]** Generate → Tier-1 validate → structural validate → map issues to deterministic repairs (static table over EPUBCheck message ids and our structural codes) → regenerate → re-validate. Termination: lexicographic measure `M = (fatal, error, warning)` must strictly decrease and no new message id may appear; content hash per iteration detects oscillation; at most one repair per `(file, node)` per iteration in a fixed order; cap 3. **Repair-fire rate on the corpus is a release metric with target zero** — every repair that fires is an emitter bug. After the cap: the EPUB is still written, the report is marked `invalid`, the UI says so plainly.

**D13.8 Cache and reproducibility.** Content-addressed file cache keyed by `sha256(model_id ‖ prompt_version ‖ grammar_hash ‖ input)`; every LLM decision records model, prompt version, input/output hashes. Determinism contract: `--no-ai` output is byte-identical on the same OS and version and is tested for cross-OS identity in CI (pure-Rust image codecs); AI runs are byte-identical on cache hit; cold AI runs are not guaranteed bit-reproducible (llama.cpp greedy decoding varies with thread count).

**D13.9 Privacy by construction.** Core crates have no HTTP client dependency (`cargo-deny` bans); only `oc-net` opens sockets (model download host allowlist; BYO endpoint); the conversion path never touches the network (CI runs the conversion suite under `unshare -n`); Tauri capabilities grant the webview no `http` permission; CSP `connect-src 'none'`. No telemetry, no crash reporting; "Report a problem" exports a diagnostic bundle the user reviews and sends themselves. On Linux ≥ 5.13 **Landlock** (v1, Phase 14, self-applied before the first PDF byte, graceful recorded skip otherwise) makes this claim kernel-enforced rather than only dependency-enforced — on ABI ≥ 4 it also blocks `connect()`. Security reports come in privately through **GitHub Security Advisories**.

**D13.10 Per-page classification is a first-class, user-overridable verdict:** `text` / `broken-text` (bad CMap) / `ocr-sandwich` (render-mode-3 layer, `GlyphLessFont`) / `image-only` / `mixed` / `blank`. Routing: `broken-text` and `image-only` → OCR if available, else page image + warning; `ocr-sandwich` → use the existing layer with `provenance = ocr-layer` and low confidence, offer re-OCR; `mixed` → OCR only image regions not covered by text, insert as blocks positioned by bbox. Document classification (`book-prose`, `academic-multicolumn`, `scanned`, `slides/other`) and `/Producer`/`/Creator` fingerprint are recorded in the report and used to pick a preset; producer-specific parameter rules are kept to a short, explicit table.

**D13.11 Other settled policies.** Config: TOML, precedence `CLI > job-spec > user config > preset > defaults`, applied **key by key**: a preset is a *partial override map over `thresholds.toml` keys by name*, so a preset that sets `paragraphs.unwrap_factor` overrides that key and nothing else and every other key still resolves from `thresholds.toml` with its own `source`/`owner`/`review_by` provenance intact. Preset overlays are declared inside `thresholds.toml` so D17's rules apply uniformly to every number. Document presets `auto|novel|academic|textbook|poetry|scanned`; the UI **quality presets** `fast|balanced|thorough` are key-by-key threshold override maps of exactly the same kind. Thresholds in `thresholds.toml` (D17). Images: pass JPEG through when already ≤ target, else re-encode; longest side ≤ 1600 px (provisional); SMask composited to PNG with alpha; CMYK→sRGB naïve in v1 (flagged); ornaments dropped when a small identical image repeats on ≥ 30 % of pages; vector regions rasterized at 2× in v1 (SVG post-v1); warn when EPUB > 50 MB. CSS: one `style.css`, no `font-family`, no absolute sizes, relative units only; classes `verse`, `stanza`, `dropcap`, `smallcaps`, `caption`, `pagebreak`. Chapter splitting: one XHTML per part/chapter/front-/back-matter section, then at 260 KB on paragraph boundaries; spine = reading order; nav targets heading ids; `page-list` spans files. Language: `dc:language` from `whatlang` (MIT, small) over the body; per-block `xml:lang` only for ≥ 5 words, high margin, and < 20 % of blocks. Encrypted PDFs: open with empty user password; prompt/`--password` otherwise; owner-password permission flags do not block conversion (recorded in report). Fonts: no embedding in v1; warn on rare-script glyph ranges. Threading: `rayon` per page in extraction/images; stages sequential; progress via a sync callback trait. Performance budget (provisional, reference machine L): ≤ 0.5 s/page and ≤ 500 MB peak RSS for a 300-page born-digital book (Docling's heavier pipeline: 0.41–1.06 s/page). Missing/corrupt sidecar with AI enabled: convert deterministically, non-modal banner + report note.

## D17. Thresholds policy (operational, not rhetorical) [RT]

`thresholds.toml` is the single source of every numeric constant. Each entry carries `{value, source: binary|published|provisional|calibrated, evidence, owner, review_by}`. CI fails on a `provisional` entry without owner or with an expired `review_by`. **v1 ships `ai.enabled = false`**; escalation uses structural predicates (metadata absent/boilerplate; no outline and TOC parse < 3 entries; > 1 heading cluster with numbering coverage < 100 %; dehyphenation joined form unattested → keep hyphen; indent present and short-line ratio in [0.35, 0.75]). `eval calibrate` later fits per-signal thresholds by the risk-coverage method against a false-repair-rate target ≤ 1 % per category, on **real-producer strata only** (never on our own renderers' output), with reliability diagrams (adaptive binning) attached to the promoting commit.

## D18. Corpus honesty [RT]

Synthetic PDFs (Typst/WeasyPrint from Standard Ebooks CC0 XHTML) are the ground-truth factory, but they lack the defects behind most real failures (bad CMaps, Type 3, fake bold, OCR sandwiches, InDesign spacing) and Typst tags PDFs by default while reality is 12.6 % tagged. Therefore: struct trees are stripped from synthetic fixtures by default (tagged variants are a separate ~12 % bucket); the corpus is stratified by `/Producer` (`pdfTeX`, `InDesign`, `Word`, `Ghostscript`, `ABBYY/scanner`, `ours(Typst)`, `ours(WeasyPrint)`, `unknown`) and reported per stratum; `ours(*)` ≤ 40 % of the corpus and a release cannot pass on `ours(*)` alone; real books come from OAPEN/DOAB (CC BY / CC BY-SA subset), Internet Archive PD scans, arXiv CC-BY, US-Gov, EU CC-BY; a ≥ 100-file real-world holdout is frozen and never used to fit thresholds; the mutation catalogue is keyed to the failure taxonomy; the score gap between `ours(*)` and real strata is a first-class metric.
